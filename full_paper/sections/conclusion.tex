\section{Limitations and Future Work}

\subsection{Current Limitations}
\texttt{ctpb} implements the core proto3 specification. Three limitations bound the present work. P2996 static reflection is currently available only in experimental branches of Clang and GCC, pending final ISO C++26 ratification. The initial release focuses on wire serialization, and RPC service stubs are intentionally omitted. Constant evaluation is bounded first by the compiler's step limit rather than by memory: a single message of 300 \texttt{int32} fields compiles under Clang's default of $1{,}048{,}576$ steps and one of 301 does not, while \texttt{-fconstexpr-steps=4194304} compiles a 1{,}000-field message. The default is low enough that a large schema meets it, and \texttt{ctpb} does not raise it.

\subsection{Future Work}
Planned additions include Well-Known Types (\texttt{Timestamp}, \texttt{Duration}), compile-time JSON mapping (\texttt{protojson}), and asynchronous gRPC stub synthesis.

\section{Conclusion}
This paper presented \texttt{ctpb}, a header-only library for C++26 that performs Protocol Buffers serialization without external code generators. By uniting P1967 \texttt{\#embed}, \texttt{constexpr} recursive-descent parsing, and P2996 static reflection, \texttt{ctpb} compiles raw \texttt{.proto} schemas directly into type-safe, optimized C++ structures within the compiler front-end. The evaluation confirms sub-$11.4\,\mu\text{s}$ schema parsing latency, a $93.70\times$ reduction in standalone binary footprint, and serialization reaching $5{,}419.9\,\text{MiB/s}$, a $5.57\times$ speedup over \texttt{libprotobuf-lite} and $5.33\times$ over the full library. Deserialization reaches parity rather than a margin, $1.04\times$ against the lite baseline, and that figure still contains a correctness asymmetry, since \texttt{ctpb} omits the UTF-8 validation of \texttt{string} fields that proto3 requires and the reference implementation performs.
