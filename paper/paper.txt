Abstract—Serialization frameworks such as Protocol Buffers
typically rely on external code generators (protoc) to translate
schemas into C++ files, which adds build rules, version coupling,
and generated source. This paper presents ctpb, a header-only
C++26 library that uses static reflection to parse .proto schemas
and synthesize C++ types during compilation. The library carries
the schema in the translation unit as a compile-time string,
performs a constexpr recursive-descent parse into an Abstract
Syntax Tree, and materializes type-safe fields and wire-format
visitors without generated .pb.h or .pb.cc files. On one host,
a synthetic 100-field schema is parsed in 7.487 µs (range 7.442
to 7.515 µs). For a 47-byte, three-field Person workload, ctpb
encodes 4.80× faster than libprotobuf 3.21.12, while decoding
leads by 1.26× to 1.46× and includes proto3 UTF-8 validation.
A stripped sample executable is 18,792 bytes versus 1,759,368
bytes for the generated-code static-runtime comparison. Removing
the generator relocates its cost into the front end rather than
eliminating it: the same schema at 100 fields builds 2.87× more
slowly than the generated path. Wire-format fidelity is verified
bidirectionally against the reference implementation.
Keywords—Protocol Buffers, C++26, Static Reflection, CompileTime Metaprogramming, Zero-Codegen Serialization

A. Encoding
The serialization engine in ctpb::wire manipulates the
byte stream directly, without intermediate buffers. Encoding
proceeds in two passes: byte_size() computes the exact
wire length from compile-time field metadata, the output buffer
is allocated once, and the fields are then written through a
raw pointer with no reallocation or virtual dispatch. Varints
emit seven payload bits per byte with the high bit signalling
continuation; signed integers are Zigzag-converted with shifts
and XORs; and repeated numeric scalars, which proto3 packs
by default, have their payload size computed inline and are
written as one contiguous length-delimited record under a single
tag.
B. Deserialization and Error Recovery
The ctpb::wire::reader operates on a non-owning
std::span<const std::byte> and bounds-checks every read: varint decoding refuses to advance past the buffer end
or beyond the ten-byte maximum width, and length-delimited
reads validate the declared length against the remaining
bytes before yielding a subspan. ctpb::decode returns
failures as std::expected<T, decode_error> rather
than throwing, so decoding remains usable in noexcept
contexts.
Unknown field numbers are tolerated during decoding. The
skip_field method uses the wire type alone to advance past
an unrecognized integer, fixed-width block, or length-delimited
payload, allowing an older ctpb reader to consume a message
containing newer fields. Skipped fields are not retained for
re-serialization.
VII. E XPERIMENTAL E VALUATION
All results in this section come from one sitting on
13 September 2026: an AMD Ryzen 7 5800H with 16
logical CPUs running Linux 7.2.3. Every CPU ran at the
performance scaling governor for the duration, as the
run’s own environment capture records. No frequency samples
accompany this sitting’s record. The timed work ran in a
container image built from the project’s own recipe [6], using
the experimental Clang 21 branch that implements P2996,
-std=c++26 -freflection -O3, and Protobuf 3.21.12.
The reflection implementation is the one measured: the P2996
feature gate is verified open in the measured configuration, and
the same command with -stdlib=libstdc++ closes it,
because <meta> ships only with libc++. Trial 0 is excluded
as a warm-up; all tables report the median and full range of
the six retained trials. The results describe this host and these
workloads, not performance across machines. Raw trial lines,
the environment record, and the scripts that produced them are
published with the artifact [6].

IX. L IMITATIONS AND F UTURE W ORK
The present work has five limitations. First, the evaluated
implementation requires an experimental Clang P2996 branch,
so deployment depends on the compiler revision recorded with
the benchmark artifact. Second, the initial release covers wire
serialization only: gRPC service stubs are out of scope, and
integration with a gRPC runtime is untested, Section VII-E
covering the framing alone. Third, constant evaluation is
bounded first by the compiler’s step limit rather than by
memory: a single message of 317 int32 fields is synthesized
under Clang’s default budget, while 318 fail. The bound is
a flag rather than a wall, since raising the budget compiles
3,200 fields without reaching a ceiling, but ctpb does not
raise the default. Fourth, the decoding margin is specific to the
libprotobuf 3.21.12 baseline; an unpaired run of 36.0.0
decoded the same message faster than the figure measured
here for ctpb, so decoding is not claimed as a lead over
Protocol Buffers in general. Finally, the performance data
comes from one host and a limited set of synthetic schemas
and one 47-byte Person message. Future work targets the
Well-Known Types (Timestamp, Duration), compile-time
JSON mapping, broader workload coverage, and asynchronous
stub synthesis.
X. C ONCLUSION
This paper presented ctpb, a header-only C++26 library that
performs Protocol Buffers serialization without generated C++
source. By combining constexpr recursive-descent parsing
with P2996 static reflection, ctpb compiles .proto schemas
directly into type-safe C++ structures in the compiler frontend. On one host, a 100-field synthetic schema is parsed in
7.487 µs, and the tested 47-byte Person workload encodes
4.80× faster than libprotobuf 3.21.12 while including

UTF-8 validation, and the exercised cases pass bidirectional
wire-format interoperability tests. The static-runtime generated
comparison is 93.62× larger as a file than the ctpb sample,
while the dynamic comparison is 1.46× larger; measured as
.text, however, ctpb carries more code than the dynamic
stub and far less than the bundled runtime. The removed
generator’s cost reappears in the front end, where at 100 fields it
exceeds it. These results show that static reflection can remove
generated Protocol Buffers source for the evaluated schemas and
toolchain while retaining tested wire-format interoperability.
