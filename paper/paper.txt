Abstract—Serialization frameworks such as Protocol Buffers
typically rely on external code generators (protoc) to translate
schemas into C++ files, which adds build rules, version coupling,
and generated source. This paper presents ctpb, a headeronly C++26 library that uses static reflection to parse .proto
schemas and synthesize C++ types during compilation. The library
carries the schema in the translation unit as a compile-time
string, performs a constexpr recursive-descent parse into an
Abstract Syntax Tree, and materializes type-safe fields and wireformat visitors without generated .pb.h or .pb.cc files. On
one host, a synthetic 100-field schema is parsed in 7.239 µs
(range 7.227 to 7.256 µs). For a 47-byte, three-field Person
workload, ctpb encodes between 5.38× and 5.59× faster than
full and lite libprotobuf, while decoding remains near parity
(between 1.09× and 1.10×) and includes proto3 UTF-8 validation.
A stripped sample executable is 18,776 bytes versus 1,759,368
bytes for the generated-code static-runtime comparison. Wireformat fidelity is verified bidirectionally against the reference
implementation.
Keywords—Protocol Buffers, C++26, Static Reflection, CompileTime Metaprogramming, Zero-Codegen Serialization

A. Encoding
The serialization engine in ctpb::wire manipulates the
byte stream directly, without intermediate buffers. Encoding
proceeds in two passes: byte_size() computes the exact
wire length from compile-time field metadata, the output buffer
is allocated once, and the fields are then written through a
raw pointer with no reallocation or virtual dispatch. Varints
emit seven payload bits per byte with the high bit signalling
continuation; signed integers are Zigzag-converted with shifts
and XORs; and repeated numeric scalars, which proto3 packs
by default, have their payload size computed inline and are
written as one contiguous length-delimited record under a single

VIII. R ELATED W ORK
Prior C++ work has moved from template techniques to
constexpr evaluation and reflection; P2996 supplies the
type-synthesis facilities used here, and P1967 the standardized
resource inclusion [4], [5]. CTRE illustrates compile-time
processing of a domain-specific grammar [8]; ctpb applies
the same broad idea to proto3 parsing and schema-driven
types. In serialization, reflect-cpp derives schemas from existing
C++ structs, whereas FlatBuffers and Cap’n Proto retain
standalone compilers [2], [3], [9]. ctpb instead treats proto3
as the external schema authority while avoiding generated C++
source.
